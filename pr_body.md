## Phase 19 — audio robustness under real-room noise conditions

Every ASR and wake-word test since Phase 10 fed the real engines **clean** audio: a
Piper-synthesized phrase over synthetic silence. That proved the engines work at all,
but never asked what a real room does to them — background hum, a door clattering, a
second person talking. That gap is very likely the biggest reason the still-pending
**live human test** (open since Phase 9) could disappoint. This phase derisks it with
real, CI-provable engineering — and, unlike prior phases, its headline deliverable is
partly a **measurement**: real numbers, not a target the tests were tuned to hit.

### What's in this PR

- **Noise-augmented fixtures at defined SNR levels.** Three synthetic noise beds —
  `hum` (steady low-frequency), `transient` (bursty clatter), `babble` (a competing
  talker) — generated by `tests/fixtures/make_noise_fixtures.py` (integer-only →
  byte-identical everywhere), **checksum-pinned in `MANIFEST.md`** and verified
  fail-closed in CI, then mixed into the clean speech/wake clips at **clean / +10 / 0 /
  −5 dB** (`tests/audio_mix.hpp`).
- **Measured real degradation.** `tests/audio_robustness_test.cpp` runs the real
  whisper.cpp (`tiny.en`) and openWakeWord engines against every bed × SNR combination
  and records the *actual* accuracy / detection scores. The measured table is in
  `docs/STATE.md` (reproduced locally against the real engines on this branch).
- **A basic single-mic pre-processing stage** (`common/include/echo/audio_dsp.hpp`:
  high-pass + gentle noise gate + AGC), wired into the SDL capture path
  (`sensor-pipeline/src/real_sources.cpp`) and evaluated against the same noisy clips.
  **Single-mic by design** — confirmed against the real capture code that it is one
  mono mic, so **no beamforming** was built.
- **A noise-driven confidence signal into the EXISTING safe-mode gate.** Perception
  estimates the utterance SNR and folds it into the transcript confidence, so noisy
  audio drops below the unchanged 0.72 gate and rides the **Phase-17** "ASR degraded →
  ask again calmly" fallback — no parallel mechanism.

### Honest findings (see `docs/STATE.md` for the full table + caveats)

- Both engines were **markedly robust** to these synthetic beds — recognized / fired at
  every level including −5 dB. Stated with its caveat: SNR is defined on whole-clip RMS
  over a TTS clip with silence padding, and synthetic stationary noise is gentler than a
  real room. "Robust here" ≠ "robust in a real room."
- The high-pass **measurably lifts SNR on the steady-hum bed** (−0.3 → +9.3 dB at −5 dB)
  and honestly **does little for spectrally-overlapping babble** — where a single mic
  fundamentally can't help. It didn't change already-correct output; that's the honest
  account, not a rescue arc.
- The noise gate **fires exactly on stationary noise** (≤ 0 dB hum/babble → ask again)
  and **correctly abstains on bursty transient** noise (clean speech between clatters).
  Deliberately conservative — the right bias for a memory-loss wearer (principle #5).

### Constraints honored

- Thresholds **not** tuned to flatter the result; −5 dB genuinely didn't break `tiny.en`
  on these beds and the doc says so plainly.
- **Stub build stays dependency-free** — all **12 stub suites remain green**; the whole
  measurement lives in the real-engines CI job.
- Reuses the Phase-17 degradation vocabulary; single-mic verified against real capture
  code (no assumed array).

### What this does NOT derisk (new gap #13, permanent-until-hardware)

Validates against *synthetic* noise mixed into *clean* fixtures — not a real mic's
frequency response, echo off real walls, or a real human moving. It **narrows** the
live-human risk with measured evidence; it does not remove the need for the live run.
